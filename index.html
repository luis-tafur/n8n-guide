01 · What it actually is

It's LEGO for the internet.

Imagine every app you use — Gmail, Slack, Notion, ChatGPT, Stripe, Shopify — has a little door on the back that other software can knock on. That door is called an API. n8n is a tool that lets you knock on those doors and pass information between them. No installing things. No terminal. No coding. You drag boxes around a screen and connect them with lines.

Each box is a node. A node represents one action: "get the latest emails from Gmail", "send a message to a Slack channel", "add a row to a spreadsheet". You decide the order, you decide what happens when, and n8n runs the whole thing for you — either when you click a button, on a schedule, or when something triggers it (like a new sale on your store).

Think of n8n as the kitchen of a restaurant. Each chef station (node) does one thing: one chops vegetables, one grills, one plates. The recipe (workflow) tells them the order. You — the head chef — design the recipe once, and then dinner gets made the same way every night, automatically. You only step into the kitchen if something goes wrong.

i.

You can build real things, fast

Most useful workflows take 15–60 min to build, including learning the relevant nodes for the first time.
ii.

It speaks to 400+ apps natively

Notion, Airtable, Slack, Gmail, Postgres, OpenAI, Anthropic, Stripe, Shopify, Discord, Twitter/X, YouTube, HubSpot, Salesforce, Linear, Jira… and if it's not in the list, the HTTP Request node talks to any API on the planet.
iii.

You stay in control of your data

You can run n8n on your own server (called "self-hosting") so the data flowing through your workflows never leaves machines you control. Or use their Cloud version if you don't want to deal with hosting.
iv.

It's source-available + has a generous free tier

Self-hosted = free forever for personal/internal use. Cloud has a free trial and paid plans from ~$20/mo. Either way, you're not locked in like with most SaaS tools.
02 · Getting it running

Two ways to start: 15 seconds, or 15 minutes.

Before you can do anything, you need a running n8n instance. There are two paths. If you're brand new and just want to play, pick n8n Cloud. If you're privacy-conscious or want to host on your own server, pick Self-host. Both give you the exact same product — same editor, same nodes, same workflows.

04 · Jargon, decoded

Six scary-sounding words in plain English.

You don't need to know any of these deeply to start. But you'll see them in the UI and in tutorials, so let's defuse them right now.

word 01
{ }

JSON

A way of writing structured data that humans and computers can both read. Looks like this: { "name": "Lucy", "email": "lucy@x.com", "plan": "pro" }. That's it. Curly braces, "key": "value" pairs. n8n passes JSON between every node.

Why you care: every node you click in n8n shows the input and output as JSON. Reading it = knowing what's happening.
word 02
⊕

API (Application Programming Interface)

A scary name for a simple thing: it's the way one piece of software talks to another. When n8n sends a message to Slack, it's calling Slack's API. The API has rules ("here's what URL to use, here's what info to send"). Every modern app has one.

Why you care: 99% of n8n's job is calling APIs. Most n8n nodes are pre-wrapped APIs — you fill a form, n8n makes the call.
word 03
⚡

Webhook

A public URL that, when something visits it (called "posting to it"), wakes up your workflow. Stripe posts to your webhook when a customer pays. Typeform posts when someone submits a form. You can think of it as a doorbell for your workflow.

Why you care: webhooks are how things outside n8n start your workflow in real-time. No waiting, no polling.
word 04
⟳

Cron / Schedule

A nerdy word for "run this on a schedule". Cron expressions look like 0 9 * * 1 (every Monday at 9am). n8n has a friendly UI so you don't write that — you just pick "every day at 9am" from dropdowns.

Why you care: any "daily digest", "weekly report", "every 5 minutes check this" automation uses a Schedule trigger.
word 05
⚿

Credentials

Your API keys / passwords / OAuth tokens — the proof to Slack, Notion, OpenAI etc. that you are allowed to talk to them. n8n stores them encrypted, separate from your workflows. You set them up once per service.

Why you care: first time you use a new node, you'll be asked to "create credentials". It's a one-time form per app — paste an API key or click "Sign in with…".
word 06
⊟

"Items" (this one is n8n-specific)

Inside n8n, every node receives and emits a list of things — called items. If your trigger grabs 10 new Gmail messages, that's 10 items. The next node runs once per item (unless you configure it otherwise). This is the single biggest "ah-ha" moment when you learn n8n: data flows as lists, not one-at-a-time.

Why you care: 80% of confusion in n8n comes from "why is this node running 47 times?" Answer: because the previous node gave it 47 items.
05 · Anatomy of any workflow

Every workflow is made of the same 5 ingredients.

Once you understand these five, you'll be able to read any n8n workflow you find on the internet — even huge ones — without getting overwhelmed. There's nothing else.

01 / Trigger
⚡

The thing that says "go!"

Every workflow starts with one. Manual (you click a button), Schedule (every Monday at 9am), Webhook (someone submits a form), or App event (new email in Gmail, new row in Airtable, new charge in Stripe). No trigger = the workflow never runs.

Rule: exactly one trigger per workflow.
02 / Node (the worker bee)
{ }

A box that does one thing

"Send a Slack message". "Get the customer from HubSpot". "Add a row to a sheet". "Ask GPT-4 a question". You add as many as you need, in any order. Most workflows have 3–15 nodes. The biggest ones (like full AI agents) have 30+. The most useful node is HTTP Request — it talks to any API in the world, even ones n8n doesn't have a dedicated node for.

Mindset: one node = one verb. If you want to do two things, use two nodes.
03 / Connection
→

The arrow that passes the bag

The line between two nodes. It carries the output of one node into the next node. You can branch (one node has two outgoing lines that go to different places) and merge (two lines come back together).

Drag-from-handle to connect. Click the dot on a node's right edge and drag to another node.
04 / Execution
▶

One run of the workflow

Every time the trigger fires (or you click Execute), n8n creates an execution record. It saves the input and output of every node in that run. You can open any past execution and replay it node by node — this is how you debug things.

Saving lives: when something breaks, go to Executions → click the failed run → see exactly which node failed and why.
05 / Credentials
⚿

Your keychain

API keys and login tokens, stored encrypted. You create them once per app (e.g. one OpenAI credential, one Slack credential), and then any node that talks to that app reuses it. Never appear in logs, exports, or your workflow JSON.

First-time annoyance: setting up credentials feels tedious. After 10 minutes, you have them all and never touch them again.
06 · Node families

Four families cover 95% of what you'll ever do.

n8n has 400+ nodes, but they all fall into 4 buckets. Click the tabs below to see what lives in each. You don't need to memorize anything — just know that when you need to "do X", you look in family Y.

How a workflow wakes up.

A trigger node sits at the very beginning. Every other node only runs because of what the trigger gave it.

Picking the right trigger = half the design.

Ask yourself: "What makes this thing need to run?" If the answer is "I click a button", use Manual. "Every morning at 9", use Schedule. "Someone fills my form", use Webhook. "Whenever something happens in app X", use that app's trigger.

07 · Expressions — the only "code" you need

The magic syntax: {{ }}

Every field in every node has a little toggle: "Fixed" (you type a literal value, like Hello world) or "Expression" (the value is computed from data flowing through the workflow).

When you switch a field to Expression mode, you can drop in {{ ... }} — two curly braces — and inside them, write a tiny snippet that references your data. This is the only "code" you ever need to write in n8n. Below are the recipes you'll use 90% of the time. Click "Copy" to grab them.

Field from the current item

{{ $json.email }}

$json means "the item currently flowing into this node". .email reaches into that JSON to grab the email field.

Use the email of the current item.

Output of an earlier node

{{ $('Webhook').first().json.body.email }}

Jump back several nodes. $('NodeName') grabs that node's data; .first() gets the first item; then you reach into it normally. (Older syntax $node["Name"] still works but this is the modern form.)

Use the email that the Webhook node received earlier.

Dates — yesterday / 7 days ago

{{ $now.minus({ days: 7 }).toISO() }}

n8n ships with Luxon — a friendly date library. $now is the current time; .minus() subtracts; .toISO() outputs the timestamp.

Give me the timestamp for exactly 7 days ago.

Inline if / then

{{ $json.plan === "pro" ? "high priority" : "normal" }}

A "ternary": condition ? value_if_true : value_if_false. For more complex logic, use an IF node instead.

If the plan is "pro", label this "high priority". Otherwise, "normal".

Environment variables

{{ $env.SLACK_CHANNEL_ID }}

Read a config value defined outside your workflow (in n8n's settings). Lets you switch between dev / prod channels without editing nodes.

Use whatever channel ID is set in the environment.

Format a number / string

{{ $json.amount.toFixed(2) }} USD

Mix expressions with literal text. .toFixed(2) means "2 decimal places". You can also call .toUpperCase(), .trim(), etc.

Show the amount with 2 decimals, then "USD".

Get the first item from a list

{{ $json.results[0].name }}

Square brackets index into arrays. [0] = first, [1] = second, etc. (Yes, computers count from zero.)

Get the name from the first result in the list.

Fallback if a field is empty

{{ $json.nickname || $json.name }}

The || means "or". If the left side is empty/missing, use the right side. Lifesaver for optional fields.

Use the nickname if there is one — otherwise the real name.

08 · Hands-on tutorial

Let's build one together: "alert me when a big lead fills my contact form, and have AI summarize what they want".

This is the most important section of the guide. Walk through it once — really do it, don't just read — and you'll have done every fundamental move n8n offers. Triggers, branching, calling AI, sending messages, saving data. After this, every other workflow you'll ever build is just a remix of these five moves.

What we're building

Imagine your business website has a "Contact us" form where prospects type their name, company, budget, and what they need. When someone fills it, three things should happen instantly and automatically:

  1. Only big leads matter — if the budget is over $5,000, we follow up. Otherwise, we ignore it.
  2. AI reads the lead's message and writes a 2-sentence summary + suggested follow-up action.
  3. Your sales team gets a rich Slack ping; the lead's data + AI summary lands in a master spreadsheet.

That's it. Zero servers, zero code, ~10 minutes to build. Here's the final flow:

Step 01 — Trigger

Create a new workflow and drop in the Webhook trigger

We need a door for the form data to come in through. That door is called a Webhook — n8n gives you a public URL that, when anyone POSTs data to it, fires off your workflow.

  1. Open n8n. In the left sidebar, click Workflows, then the + Add workflow button in the top-right.
  2. You'll land on an empty checkered canvas with a single big + button in the middle. Click it.
  3. A node-picker panel slides in from the right. In the search field, type webhook.
  4. Click the first result: Webhook (the one with the lightning bolt icon). The picker closes and a Webhook node appears on your canvas.
  5. The right-hand inspector opens automatically. Set HTTP Method = POST and Path = lead-form (you can pick any path name — it becomes part of the URL).
  6. Leave Respond as Immediately. This means the workflow will respond "200 OK" instantly while the rest of the flow keeps processing.
  7. At the top of the inspector, you'll see two URLs: Test URL and Production URL. Copy the Test URL to your clipboard.
  8. Click the orange button: Listen for test event. The node will start listening for 120 seconds (the official window — if no request arrives in that time, click the button again).
  9. Open your terminal (or use a tool like Postman) and send a test POST request — see the command below the screenshot.
  10. Switch back to n8n: a green checkmark appears on the node, and the right-side OUTPUT panel fills with the JSON you just sent.
# Paste this in your terminal — replace the URL with your Test URL curl -X POST https://your-n8n.io/webhook-test/lead-form \ -H "Content-Type: application/json" \ -d '{ "name": "Lucy Chen", "email": "lucy@acme.com", "company": "Acme Corp", "budget": 8000, "message": "Hi! We are a 50-person team looking for workflow automation. We need Stripe + Notion + Slack integrations. Can we schedule a demo this week?" }'
Common mistake: using the Production URL while building. The Production URL only works when your workflow is set to "Active" in the top bar. While developing, always use the Test URL + click "Listen for test event" before sending requests. n8n will throw a confusing "webhook not registered" error otherwise.
Why we do it this way: by sending a real test request now, n8n captures the exact shape of the JSON your form will send. From this point on, all other nodes can "see" those fields (name, email, plan) and you can drag them into other fields. No guessing.

Step 02 — Logic

Add an IF node to filter only big-budget leads

Not every contact form submission is a hot lead — only the ones with a real budget. We'll skip anyone under $5,000. The IF node has two outputs: a green TRUE branch (condition matched) and a red FALSE branch (condition didn't match). We'll only continue down TRUE.

  1. Hover over the Webhook node — a small + appears on its right edge. Click and drag from it onto empty canvas space. Drop. The node-picker opens.
  2. Type if in the search. Click the If node (with the question mark icon).
  3. A new IF node appears, automatically connected to the Webhook node. The inspector opens.
  4. You'll see an empty Conditions section. Click + Add Condition.
  5. Pick condition type: Number. We're comparing the budget field, which is a number (not text).
  6. On the Value 1 (left side) field, click the small { } icon to switch to Expression mode. The field turns yellow-green.
  7. Now look at the left side of the screen — there's an INPUT panel showing the JSON from the Webhook. Find the body.budget field and drag it right onto the Value 1 input. n8n writes {{ $json.body.budget }} for you automatically.
  8. For Operation, pick is greater than from the dropdown.
  9. For Value 2 (right side), leave it in Fixed mode and type 5000.
  10. Click Execute previous nodes at the top of the inspector to test. Look at the output — you should see the item in the true branch (since our test budget of 8000 is greater than 5000).
The drag-from-INPUT trick is the most important skill in n8n. You almost never have to type expressions by hand — open the left INPUT panel, find the field you want, drag it into any input. n8n writes the correct expression every time. Memorize this move.
Common mistake: picking String condition type when you're comparing numbers. If you pick String, the comparison "8000 > 5000" actually compares as text alphabetically and fails. Always match the type to the actual field shape: numbers → Number, text → String, dates → DateTime, true/false → Boolean.

Step 03 — Enrich with AI

Have OpenAI summarize the lead's message in 2 sentences

The lead wrote a long message. Your sales team doesn't have time to read every full message — they want the gist instantly. We'll send the message to GPT-4o-mini and get back a 2-sentence summary plus a suggested follow-up action.

  1. From the true output of the IF node (top exit point), drag a connection onto empty canvas.
  2. Search openai in the picker. Click the OpenAI node.
  3. In the inspector, the Credential dropdown is empty. Click + Create new credential.
  4. Open platform.openai.com/api-keys in another tab, click Create new secret key, copy it (starts with sk-...).
  5. Back in n8n: paste your key into the API Key field. Click Save. The credential is now stored encrypted.
  6. Back in the main inspector: Resource = Text, Operation = Message a Model.
  7. For Model, pick gpt-4o-mini (cheap and fast — ~$0.0001 per call).
  8. Under Messages, click + Add Message. Set role to user. For the content, switch to Expression mode and paste the prompt below the screenshot.
  9. Toggle Simplify Output to ON — this gives you just the response text, instead of OpenAI's full API response object.
  10. Click Execute node. After ~2 seconds, the OUTPUT panel shows the AI's 2-sentence summary.
# Prompt to paste into the OpenAI message content (Expression mode) You are a sales assistant. A new lead just filled our contact form. Their message: "{{ $json.body.message }}" Their budget: ${{ $json.body.budget }} Return ONLY two sentences: 1. A 1-sentence summary of what they need. 2. A 1-sentence suggested next action for our sales team.
Why we use the dedicated OpenAI node instead of HTTP Request: n8n wraps OpenAI's API in a friendly form — model dropdown, message builder, automatic token counting, error handling. You could call api.openai.com/v1/chat/completions via HTTP Request with Bearer Auth, but the dedicated node is faster and harder to break.
Common mistake: forgetting to enable Simplify Output. Four full workflows you can actually build this weekend.

① "Daily AI news digest" in your inbox at 8am

Every morning at 8am, scrape AI-related headlines, summarize them with GPT, and email yourself a clean digest. Replace "AI" with any topic.

10 · Patterns to copy

Six moves you'll repeat a thousand times.

Once you've built a few workflows, you'll start noticing the same shapes appear over and over. Memorize these — they're the bread and butter of professional-grade automations.

Fan-out / Fan-in

Split → process → Merge
⊥

You have 100 orders. Each needs an API call to enrich it. You run them in parallel, then Merge them back into a single list before saving to your database.

When: any time you have a list of things that each need work, and you want it fast.

Polling with cursor

Schedule + last-run timestamp
↻

Every 5 minutes, read your "last processed time" from a database / variable. Ask the API only for items after that timestamp. Update the cursor when done. Never re-process the same data twice.

When: the app you care about doesn't offer webhooks and you don't want to re-process the whole history.

Centralized error workflow

Error Trigger → Slack #alerts
⚠

One workflow has just an Error Trigger + a Slack node. In every other workflow's settings, set this one as the "Error workflow". Now any failure anywhere pings #alerts with the workflow name and execution ID.

When: always. It's the difference between knowing things broke and finding out a week later.

Idempotency by lookup

SELECT before INSERT
≠

Before saving anything, look it up by a unique ID (Stripe charge ID, Shopify order ID, email). If it exists, skip or update. If not, insert. Protects you from duplicate webhook deliveries and retries.

When: any workflow that writes to a database. Non-negotiable.

Respond fast, work slow

Respond to Webhook node
↩

The webhook trigger sends "200 OK" back instantly, then the rest of the workflow runs at its own pace. Stripe, Shopify, Zendesk all expect < 5s acknowledgement or they retry — even if your actual work takes 30 seconds.

When: any incoming webhook from a real service.

Sub-workflows for reuse

Execute Workflow node
⊞

If three workflows all need to "find a customer in HubSpot, then Salesforce, then your CRM, then merge the results", build that logic once and call it from all three with the Execute Workflow node.

When: you find yourself copy-pasting groups of nodes between workflows.
11 · AI in n8n

n8n is, secretly, an AI workflow builder.

n8n has gone hard on AI nodes since 2024. You can build chatbots, RAG (retrieval-augmented generation) systems, agents with tool use, and full LangChain-style pipelines — all visually. For a vibe coder, this is the killer feature. Here's the three pieces that matter:

★

AI Agent node

Give it a system prompt, attach "tools" (other nodes!), and it figures out which ones to call to answer a user's question. Want an agent that can look up customers in your DB and reply on Slack? That's literally 3 nodes: Chat Trigger → AI Agent (with Postgres + Slack as tools) → done.

⊟

Vector stores

Pinecone, Supabase, Qdrant, Postgres pgvector, etc. — all as nodes. Upload your docs once, then query them in any workflow. The "Retrieval" sub-node feeds context to your LLM automatically. Build a "chat with your PDFs" in an afternoon.

≡

Structured output

Tell the LLM to return JSON with a specific shape (categories, scores, fields). n8n validates it and gives you typed fields downstream. No more parsing "the model said 'yes I think' " — get back { category: "bug", urgency: 4 }.

The model used to be the hard part. Now it's a 5-second config: pick the provider, paste an API key, type a prompt. The hard part — orchestrating when to call it, with what data, and what to do with the answer — is exactly what n8n is good at.

12 · Error decoder

The red boxes you'll see, and what they actually mean.

When a node fails, it turns red and shows a message. Here are the most common ones, decoded into human language with the actual fix:

401 Unauthorized · Authentication failed
What it means: the API didn't like your credentials. The API key is wrong, expired, or for the wrong account.
Fix: open the node's credential, paste the key fresh, click "Save". For OAuth, click "Reconnect".
429 Too Many Requests · Rate limit exceeded
What it means: you hit the app's "no more than X calls per minute" wall.
Fix: add a Wait node before the action (e.g. 2s between calls), or use Loop Over Items with smaller batches. Many nodes have a "Retry on fail" toggle in their settings.
Cannot read property 'X' of undefined
What it means: your expression tried to grab a field that doesn't exist on this item. Maybe sometimes the field is missing.
Fix: use a fallback: {{ $json.field || "" }}. Or add an IF / Filter before this node to skip items without the field.
Webhook URL is not registered
What it means: you're hitting the Test URL but you didn't click "Listen for test event" first; or you're hitting the Production URL but the workflow isn't Active.
Fix: activate the workflow (toggle in the top bar) and use the Production URL, OR click "Listen for test event" and use the Test URL.
No data returned · empty array
What it means: the previous node ran successfully but didn't produce any items. Everything after will be skipped silently.
Fix: check the previous node's OUTPUT panel. Maybe your filter is too strict, or your query returned nothing.
Execution stopped: workflow execution timeout
What it means: the workflow ran longer than n8n's max duration (default ~5 min on Cloud, configurable on self-hosted).
Fix: split the work — process in batches with Loop Over Items, or use a Webhook + Respond Now + Execute Workflow async pattern.
JSON parameter needs to be valid JSON
What it means: you typed something into a field that expects JSON, but it's malformed (missing comma, unquoted key, etc.).
Fix: paste your JSON into jsonlint.com to find the typo. Or switch the field to Expression mode and let n8n build the object for you.
13 · Lessons learned the hard way

Unwritten rules that save you a week.

DO

Name your nodes.

"HTTP Request" tells you nothing. Rename it to get-stripe-charges. Then when you reference it elsewhere ($node["get-stripe-charges"]), the workflow reads itself. When something breaks at 3am, future-you will love past-you.

DON'T

Don't dump business logic into Code nodes.

It's tempting: "one 80-line JS function would solve everything". The problem: no one else can read it, you can't debug visually, and item handling gets weird. If you need that much code, it probably belongs in a small backend service — not a workflow.

DO

Use Pin Data while building.

After a node runs successfully once, right-click → Pin Data. n8n then reuses that cached output instead of re-calling the real API. You can iterate the rest of the workflow forever without burning API calls or hitting rate limits.

PRO

The right-hand panel is your console.

Click any node after a run. Left = INPUT (what came in), right = OUTPUT (what this node produced). Switch between "Table / JSON / Schema" views. The Schema view tells you the exact paths to use in {{ $json.path }} expressions — copy-pasteable.

DON'T

Don't trust webhooks to fire exactly once.

Stripe retries. Shopify retries. You yourself will manually "resend" when something fails. If your workflow isn't idempotent (lookup-before-write), you'll see duplicates in production within a week. Dedup by an external ID before any database write.

DO

Export your workflows to JSON and put them in Git.

Settings → Download. The file is a clean JSON — diffable, mergeable, restorable. Even if you never set up CI/CD, having a versioned copy in a private GitHub repo saves you from accidental deletes and gives you change history.

PRO

Each node decides how to run: once per item, or once for all.

In the node's Settings tab: "Run Once for All Items" vs "Run Once for Each Item". HTTP Request that needs 1 call per item? Use the second. Code that aggregates everything into a single thing? Use the first. Mixing them up causes the most baffling bugs in n8n.

DON'T

Don't paste API keys into node fields.

Always use Credentials, even for "it's just a test key". Workflows get exported, shared, accidentally committed. Credentials stay encrypted in n8n's keystore and never appear in the workflow's JSON.

DO

Browse Templates before building from scratch.

n8n's template gallery has hundreds of pre-built workflows. Search "Notion CRM", "Slack reminder", "RSS digest" — odds are someone already built ~80% of what you want. Import, tweak, rename. Don't reinvent.

PRO

Sticky Notes are documentation.

Right-click canvas → Add Sticky Note. They're colored boxes you can place anywhere with markdown text. Use them to label sections ("everything below = email pipeline") and to leave warnings ("don't change order — the API rate-limits us"). Future-proof your workflow against the version of you that forgot.

14 · Glossary

Every word you'll hear in any n8n conversation.

Workflow
The whole automation — your canvas with all its nodes and connections. One file, one job.
Node
One box on the canvas. Does one thing. Has inputs (data coming in) and outputs (data going out).
Item
A single JSON object passed between nodes. A node always receives a list of items, even if there's just one.
Binary data
Files — PDFs, images, etc. — that travel alongside the JSON. Handled separately because they're not text.
Execution
A single run of a workflow. Has input, output per node, status (success/error), and duration. Saved in the Executions log.
Trigger node
The very first node. Without one, the workflow can't start. Only one allowed per workflow.
Credential
Stored login info for an external app (API key, OAuth token, etc). Made once, reused by every node that talks to that app.
Expression
Anything inside {{ }}. A tiny JS snippet that pulls dynamic data into a field at runtime.
Sticky note
A colored note you place on the canvas for documentation. Does nothing — it's just for humans reading the workflow.
Sub-workflow
A workflow called from another workflow (via Execute Workflow node). Useful for encapsulating reusable logic.
Active vs Inactive
The toggle in the top bar. Active = triggers are live and the workflow runs in production. Inactive = only runs when you manually click Execute.
Test URL vs Production URL
(Webhooks only.) Test URL only listens while you're in the editor with "Listen" enabled. Production URL listens 24/7 — but only if the workflow is Active.
Self-hosted
You run n8n on your own server (Docker, k8s, Railway, etc.). Free for internal use. Versus n8n Cloud, which is their hosted SaaS.
Community node
A third-party node not built by the n8n team. Self-host only. Lets you extend with weird custom integrations.
Pin Data
Right-click on a node → Pin Data. Freezes its output. Future runs use the frozen data instead of re-calling the real API.
AI Agent
A specialized n8n node that uses an LLM to decide which other nodes (called "tools") to call. The basis for building chatbots and autonomous helpers.
